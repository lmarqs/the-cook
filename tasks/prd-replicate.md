# PRD: `./cook replicate`, re-cook a recipe from what `cook.lock` recorded

## Overview

A recipe whose output stays out of commits leaves every new clone or worktree with the committed `cook.lock` entry but
none of the files. `io.github.lmarqs.cookbook:ralph#ralph-tui --share=clone` is the case in point: `.gitignore` keeps
all of `.ralph-tui/` out of commits, and its help says "each clone cooks its own". Today the person retypes the
original command with all of its arguments, because `cook.lock` records no arguments (ADR 0007, decision 3).

This feature makes `cook.lock` record each recipe's arguments and adds `./cook replicate <recipe>...`. The command
cooks each named recipe again, at the source and with the arguments `cook.lock` recorded, through the normal diff,
approval and `--dry-run` flow. `discard` and `replicate` both accept the recipe's lock name, such as
`io.github.lmarqs.cookbook:ralph#ralph-tui`, without a version.

## Goals

- A person in a fresh clone recreates a recipe's clone-only output with one command that names the recipe, without
  retyping arguments or looking up a version.
- Every cook records the recipe's given arguments in `cook.lock`, in the normalized form of the `cookedWith` line.
- `discard` and `replicate` both accept the version-less lock name. Every operand form `discard` takes today keeps
  working.
- An engine without this feature still reads a `cook.lock` written with it.

## Quality Gates

These commands must pass for every user story:
- `./gradlew check cliBuild jpackageTest`: build, tests, Spotless and CodeNarc (the AGENTS.md Done check)
- `git diff --check`: no whitespace errors

## User Stories

### US-001: Record each recipe's arguments in `cook.lock`
**Description:** As a person who cooks a recipe, I want `cook.lock` to record the arguments I gave so that the recipe
can be cooked again without my retyping them.

**Acceptance Criteria:**
- [ ] `RecipeRun.run` (`core/src/main/groovy/thecook/cookbook/RecipeRun.groovy:42-62`) returns the normalized
      argument list to its caller: the `line` it builds for `cookedWith`, without the recipe name. `cookedWith`
      output is byte-for-byte unchanged.
- [ ] `CookLock` (`core/src/main/groovy/thecook/cookbook/CookLock.groovy`) stores a nullable `List<String> arguments`
      per entry. `null` means "not recorded". The field is read in `parse`, taken by `record(...)`, exposed through an
      accessor `arguments(name)`, and rendered after `sha256` and before `owns` as a list of JSON-quoted strings.
- [ ] `render()` writes `arguments: []` for a recipe cooked with no arguments.
- [ ] `version: 1` is unchanged. A lock whose entries have no `arguments` key still parses, and their `arguments(name)`
      returns `null`.
- [ ] `CookbookCook.propose` (`core/src/main/groovy/thecook/cookbook/CookbookCook.groovy:51,65`) passes the
      arguments into `lock.record`.
- [ ] A new test in `core/src/test/groovy/thecook/CookbookCookTest.groovy` cooks with the inputs of the test at
      ~:1237 (`agent: [codex, claude, codex], m: [slow], file: [./b.md, a.md, b.md]`). It asserts the lock records
      `["--agent=codex", "--agent=claude", "--mode=slow", "--file=a.md", "--file=b.md"]`.
- [ ] Tests also cover `arguments: []` with none given, and the parsing of an entry without `arguments`.
- [ ] Existing lock-content assertions in `CookbookCookTest`, `RalphTuiCookTest`, `BeadsTrackerCookTest`,
      `AgentsWorktreeCookTest` and `GitWorktreesCookTest` include the new field. No assertion is loosened.
- [ ] This repository's `cook.lock` is regenerated by re-cooking its recipes with their current arguments (taken
      from the `cookedWith` lines in `.gitignore` and the other cooked files), never edited by hand. Its diff only adds
      `arguments` lines.
- [ ] Commit: `feat(core): cook.lock records the arguments each recipe was cooked with`

### US-003: `CookbookReplicate` in core
**Description:** As the CLI, I want a core operation that turns lock names into cook requests replaying the recorded
source and arguments so that replicate reuses the cook pipeline unchanged.

**Acceptance Criteria:**
- [ ] A new `core/src/main/groovy/thecook/cookbook/CookbookReplicate.groovy`, shaped like
      `CookbookDiscard.groovy:21-45`, maps each operand to a name through `RecipeLoader.name`.
- [ ] It refuses an empty operand list, a name given twice, and a name not in `cook.lock`. The last refusal lists the
      known names, as discard does.
- [ ] It refuses an entry whose `arguments` is `null` with `<name> has no recorded arguments in cook.lock` and the
      next step `cook it once with its arguments`.
- [ ] For each entry it builds `RecipeRequest(entry.source, <arguments parsed back into Argument.inline>)` and returns
      `new CookbookCook(...).propose(requests)`. The recorded `source`, including its version, decides what loads. A
      version in the operand is ignored.
- [ ] When the resolved sha256 differs from the recorded one, the changed-source notice is reported and cooking goes
      ahead. This covers coordinates (existing notice, `CookbookCook.groovy:61`) and path recipes.
- [ ] When the recorded arguments no longer bind (`Unknown argument`, a missing required param), the error adds
      `arguments recorded in cook.lock: <recorded line>` and the next step `cook it with its arguments`.
- [ ] A new `core/src/test/groovy/thecook/CookbookReplicateTest.groovy` covers:
  - a round trip: cook a recipe with arguments, delete a file it owns, replicate, and get the same files and lock;
  - a second replicate with an empty diff;
  - each refusal above;
  - a path recipe;
  - a drifted source, with the notice shown;
  - recorded arguments the recipe no longer accepts, with the prefixed error.
- [ ] Commit: `feat(core): replicate cooks a recipe again from its cook.lock entry`

## Functional Requirements

- FR-1: Every successful cook must record, in each cooked recipe's `cook.lock` entry, the list of given arguments in
  the normalized `--opt=value` form `RecipeRun` produces. It records `[]` when none are given and never records
  defaults.
- FR-2: `cook.lock` must stay at `version: 1`, and an entry without `arguments` must parse.
- FR-3: `./cook replicate <recipe>...` must require at least one operand and must refuse recipe arguments.
- FR-4: Replicate operands must match `cook.lock` names as `group:artifact#recipe`, versioned coordinates (version
  ignored) or a path recipe's path, with or without `.groovy`.
- FR-5: Replicate must load each recipe from the entry's recorded `source` and bind the recorded arguments.
- FR-6: Replicate must refuse an entry with no recorded arguments and name the next step.
- FR-7: Replicate must compose the named recipes left to right into one batch, with the same diff, approval,
  `--dry-run`, `--batch-approve` and result lines as cooking.
- FR-8: When the resolved source's sha256 differs from the recorded one, replicate must show the changed-source notice
  and cook.
- FR-9: When recorded arguments fail to bind, the error must show the recorded arguments and say they came from
  `cook.lock`.
- FR-10: `discard` must accept the `group:artifact#recipe` form, in addition to the forms it accepts today.

## Non-Goals

- Replaying every entry in `cook.lock` (`./cook replicate` with no operands, or an `--all` option).
- Resolving a newer version than the one recorded, or any upgrade flow.
- Restoring the order of the original invocation, or replaying several recipes as they were originally batched.
- `--check`, `--force` or `--skip` for replicate. `--force` and `--skip` only act on a recipe's first cook
  (`CookbookCook.groovy:114`), and replicate always has a lock entry.
- Bumping the `cook.lock` format version, or migrating old entries.
- Recording resolved defaults.

## Technical Considerations

- Replicate is a front-end over `CookbookCook.propose`. The cook pipeline (evaluation, declarations, ownership,
  writes) stays unchanged.
- `Argument` (`core/src/main/groovy/thecook/cookbook/Argument.groovy`) holds the parsed form. A recorded `--opt=value`
  string becomes `Argument.inline(opt, value)`. A yes-or-no param recorded as `--flag=true` binds as before.
- This repository's `cook.toml` is `repositories = ["cookbook"]`. `CookbookDirectory` serves any version from the
  current files, so the sha256 drift in FR-8 happens here routinely.
- `cook.lock`, `.agents/skills/agents-layout/` and the adapter keys are generated, so they change only by cooking.
- Commit subjects follow AGENTS.md. `feat` releases a minor version. No story uses `!`.
- Tracking issue: #71. Work happens on a branch at `.worktrees/<branch>`. Push after each story, and comment progress on the tracking
  GitHub issue.

## Success Metrics

- In a fresh clone, the clone-only output of a `--share=clone` recipe comes back with one `./cook replicate <name>`
  and no typed arguments or version (US-007).
- All existing tests pass unchanged, except for the new `arguments` field in lock-content assertions.
- No document says `cook.lock` records no arguments.
