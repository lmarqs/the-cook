# Investigate

Find the symptom, run its check from the repository root, and apply the fix for the cause the check confirms. Claude
Code 2.1.303 and Codex 0.160.1 were used to confirm the behavior below, except where a row says it was not tested.

| Symptom | Likely cause | Check | Fix |
| --- | --- | --- | --- |
| Claude ignores `AGENTS.md` | A `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md` exists in the directory or one above it, so Claude reads that file instead | `d=$PWD; while [ "$d" != / ]; do ls "$d"/CLAUDE.md "$d"/CLAUDE.local.md "$d"/.claude/CLAUDE.md 2>/dev/null; d=$(dirname "$d"); done` | Move what it holds to `AGENTS.md` or `~/.claude/CLAUDE.md`, then delete it; [adopt.md](adopt.md#a-root-claudemd) |
| Claude ignores `AGENTS.md` | Claude Code older than 2.1.277, which added `AGENTS.md` support | `claude --version` | Update Claude Code |
| Claude ignores `AGENTS.md` | The person turned the support off; Claude Code's changelog says it is set under "Project instructions" in `/config`; not tested here | `/config` inside a Claude session | Turn it back on |
| Claude does not offer a shared skill or command | The `.claude/skills` or `.claude/commands` link is missing or broken; Claude finds them only there | `ls -l .claude` | Cook `#connect --harness=claude`; on Windows, see the links row |
| An allowed command still prompts in Claude | The workspace is not trusted, and Claude ignores the project's allow rules until it is. `claude -p` reports `Ignoring 1 permissions.allow entry ... workspace has not been trusted` | Start `claude` in the repository and look for the trust question | Accept it once, interactively |
| An allowed command still prompts | An `ask` or `deny` from another file matches too and wins; precedence is deny, then ask, then allow, across every settings file | `grep -n '<command>' .agents/permission/policy.yaml ~/.claude/settings.json .claude/settings.local.json` | Remove the narrower entry, or agree with the team to change the policy |
| An allowed command still prompts | The command does not start with the entry's words: `git -C sub status` is not `[git, status]`, nor is `env X=1 git status` | Compare the command as run with the rendered rule in `.agents/adapters/` | Run it in the form the policy names, or add that form to the policy |
| An allowed command still prompts in Codex | The project is not trusted, so Codex does not load `.codex/rules` | `codex execpolicy check --rules .agents/adapters/codex/rules/cook.rules <command>` prints `"decision":"allow"` while the session still asks | Trust the project when Codex asks, or pass `-c 'projects."<absolute path>".trust_level="trusted"'` |
| A denied command ran | A form the prefix does not cover: arguments in another order, `git -C`, `env`, `bash -c '...'` or a script that runs it | `codex execpolicy check --rules .agents/adapters/codex/rules/cook.rules <command as run>` | Add a `claude:` pattern for the form, and accept that Codex cannot match it; [design.md](design.md#a-guardrail-not-enforcement) |
| A denied command ran in Codex | The entry is Claude-only; the Codex rules file lists it as `# Not enforced by Codex, Claude-only: ...` | `grep 'Not enforced' .agents/adapters/codex/rules/cook.rules` | Express it as a prefix if one can, or rely on Codex's sandbox |
| A denied command ran | The run skipped the policy: `--dangerously-skip-permissions`, `--setting-sources user` or `codex exec --ignore-rules` | The launch command, or the orchestrator's config | The policy cannot prevent this; agree on launch commands, or use managed settings |
| A hand edit to `.agents/adapters/` came back, or a cook proposes undoing it | The adapters are rendered from the policy, and each cook renders them again | `./cook --dry-run io.github.lmarqs.cookbook:agents:<version>#connect --harness=claude --harness=codex` | Put the change in `policy.yaml`, or for Claude keys other than `permissions`, in a file cooked with `#claude-settings` |
| A teammate's Codex or Claude files disappeared | Someone cooked `#connect` with only their own harness, which removes what Cook wrote for the other | `git log --stat -- .agents/adapters .codex .claude` | Cook `#connect` again naming every harness the team uses, and commit |
| An unattended Claude run stops or refuses a command | An `ask` entry matched. With `claude -p --permission-prompts none` anything that would ask is refused | `grep -n -A20 '^  ask:' .agents/permission/policy.yaml` | Move the entry to `allow` or `deny` if the team agrees, or keep that task attended |
| An unattended Claude run refuses commands the policy allows | The workspace is not trusted; see the first prompts row | Run it with `claude -p` and read the warning it prints | Trust the workspace once, interactively |
| An unattended Codex run stops or refuses | A `prompt` rule matched under `approval_policy=never`, which has nobody to ask; not tested here | `codex execpolicy check --rules .agents/adapters/codex/rules/cook.rules <command>` | As for Claude: move the entry, or keep the task attended |
| A role's deny does not apply | Claude: the run did not add the role's file. Codex: Codex has no roles | Claude: the launch command has `--settings .agents/adapters/claude/roles/<role>.json` | Claude: add it. Codex: [design.md](design.md#why-codex-has-no-roles) |
| On Windows, `.claude/settings.json` is a one-line text file holding `../.agents/adapters/claude/settings.json` | git checked links out as text, because `core.symlinks` is off; not tested here | `git config core.symlinks` and `git ls-files -s .claude .codex`, which shows mode `120000` for a link | Turn on Windows Developer Mode, `git config core.symlinks true`, delete those files and run `git checkout -- .claude .codex` |
| Personal approvals or a model appear in a commit | A rule saved to the project settings instead of `.claude/settings.local.json` writes through the link into the shared adapter; not tested here | `git log -p -- .agents/adapters .claude` and `git ls-files .claude .codex`, which should list only links | Revert the change, keep the rule in `.claude/settings.local.json`, or propose it in `policy.yaml` |
| Files in `.claude/` or `.codex/` other than links are committed | They were committed before the layout, or added with `git add -f`; `.gitignore` does not untrack them | `git ls-files .claude .codex` | `git rm --cached <file>` and keep it locally, or move it into `.agents/` |
