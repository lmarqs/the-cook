Recipe driven configuration

Cook the best product without any source of contamination.

the-cook writes the setup a repository shares, such as agent instructions and permissions, hooks, skills, worktree rules and ignore rules, into the native files each tool reads. Each recipe keeps to the parts it owns, and Cook writes nothing until one person approves one diff.

The lab

A repository worked by agents

Several agents and people work in one repository at once. Each harness reads its own files, and each worktree needs the same setup to run. The pins on the lab mark how Cook keeps them apart and the same.

  1. 1

    The office: one review

    Cook shows the diff of every file it would write, cook.lock included, and asks once. A failed write rolls back the writes already made.

  2. 2

    Stations: one worktree per agent

    Each agent works in .worktrees/<branch>, and reads the setup its branch commits.

  3. 3

    Suits: no contamination

    A recipe owns marked sections, keys and whole files, recorded in cook.lock. What teammates and other tools wrote beside them stays as it is.

  4. 4

    The board: native files

    Harnesses read AGENTS.md, .claude/ and .codex/ directly. Contributors who do not run Cook need nothing.

  5. 5

    Robot arms: unattended loops

    ralph-tui runs in a worktree of its own, and with --worker-check a task completes only once the team's check passes.

  6. 6

    The conveyor: cookbooks

    Recipes ship in cookbook jars on Maven Central and are cooked by coordinates, group:artifact:version#recipe.

Why

Setup copied by hand drifts

Problem

Teams reuse setup across repositories: agent instructions and permissions, editor settings, ignore rules, build and CI files. Copied by hand, the copies drift.

Those files are shared. A setup that replaces a whole file loses what teammates and other tools wrote in it, and nobody can tell which part came from where or remove a part cleanly.

Coding agents widen the problem: each harness reads its own files for instructions, permissions, hooks and skills, and each agent's worktree needs the same setup to run.

Goal

A setup learned once reaches every repository through one reviewed change, lives beside hand-written content in the same files, and is withdrawn the same way.

Contributors who do not run Cook need nothing to contribute: their programs read the native files directly, and the lock and markers Cook leaves are reviewed like any other change.

Every agent harness and every worktree reads the same reviewed setup from what its branch commits.

The philosophy gives the tenets behind every decision.

What it sets up

Recipes for repositories worked by agents

The agents, git, beads and ralph cookbook artifacts run today. Each recipe's help, read with ./cook help <coordinates>, says what it writes.

agents#seed · agents#connect

One set of instructions and permissions for every harness

#seed creates AGENTS.md and a permission policy. #connect renders the policy into Claude Code's permissions and Codex's sandbox and approval settings, with roles that narrow it for Claude Code.

agents#connect

A fresh clone that already holds the setup

The .claude/ and .codex/ links into .agents/ are committed, so a fresh clone, a cloud session or CI holds each harness's settings, hooks and skills without cooking.

agents cookbook

agents#connect · beads#tracker

Context when a session starts

Both harnesses run .agents/hooks/session-start, which adds the output of each session-start.d/*.sh to the session. beads#tracker can write one that prints the Beads prime text.

beads cookbook

git#worktrees · agents#connect

A worktree for each agent

git#worktrees states the rule .worktrees/<branch> and seeds setup and teardown scripts. With --worktree-setup, Claude Code's worktree hooks run setup in each new worktree, and removal deletes the branch only once its commits have landed.

git cookbook

ralph#ralph-tui

Unattended loop runs

bin/run runs ralph-tui in .worktrees/ralph/<name> on its own branch. bin/clean refuses to delete commits that have not landed, unless given --force.

ralph cookbook

--share=clone · replicate

Output kept to one clone

With --share=clone, ralph-tui's configuration and the Beads issues stay out of commits. replicate cooks ralph-tui's configuration again in a fresh clone from what cook.lock records.

A variant for one branch

One cook

Edit the policy, cook, review, commit

  1. Edit what the team decides

    Allow git status and git diff, deny git reset --hard, in .agents/permission/policy.yaml.

  2. Cook

    The recipe renders the policy into each harness's own settings. Cook shows the diff of every file and asks once.

  3. Commit one change

    The policy and the settings it renders go into one commit, reviewed like any other.

  4. Cook again

    Nothing changed, so Cook prints Already cooked. and asks nothing. In CI, ./cook check fails when the kitchen differs from cook.lock.

Operations

Cook, withdraw, rebuild, check

Every operation goes through the same review and the same lock.

./cook <recipe>...

Cooks recipes left to right in one batch: one diff, one question, then the writes, rolled back if one fails.

./cook discard <name>...

Removes what cook.lock lists for each recipe, without running it: its sections, keys, files and links.

./cook replicate [<name>...]

Cooks recipes, or every recipe in cook.lock, again from the sources and arguments it records, including ignored output missing from a fresh clone.

./cook check [<name>...]

Cooks the same way and writes nothing: exits 1 when the kitchen differs from what cook.lock records, 2 on an error.

Install

Pin the engine in the repository

Each release publishes Cook for Linux x64 and arm64 and macOS arm64, a complete package with its own Java runtime, and the cook wrapper.

  • {% include icons/linux.svg %}Linux x64
  • {% include icons/linux.svg %}Linux arm64
  • {% include icons/apple.svg %}macOS arm64
  • {% include icons/openjdk.svg %}Java runtime included

{% include icons/terminal.svg %}The wrapper

Commit it to pin the engine version. On first use it downloads the package for the machine and refuses it unless its sha256 matches the one written in the wrapper.

curl -fsSLO https://github.com/lmarqs/the-cook/releases/latest/download/cook
chmod +x cook
./cook --help
git add cook

{% include icons/package.svg %}mise

Installs a release package and puts its cook launcher on PATH.

mise use github:lmarqs/the-cook@{{ version }}
cook --help

Without a cook.toml, coordinates such as {{ agents }}#seed resolve from Maven Central.
