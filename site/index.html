    The lab

    A place where standards matter

    Knowledge should be easy to replicate

    Setting up a project is hard. How the code is formatted, which tools run at which version, what a build must pass, how a release is cut, how documentation is organised, how work is tracked and reviewed, how editors and agents are set up: every one of these is a decision, and the team tries and argues for weeks before each settles. Then it finally works. The project feels good to work in, and every part connects like clockwork.

    Until a second project arrives, the team improves a standard, a new developer joins, or the team moves on from a tool. Each one unsettles what took weeks to settle.

    1. 1

      One version reaches every project

      ProblemThe second project gets the standards by copying files, and the third copies whichever is newer.

      SolutionEvery project gets a standard from one place, at one version.

    2. 2

      An improvement reaches every project

      ProblemThe team improves a standard in one project, and the improvement goes no further.

      SolutionOne reviewed change reaches every project, and CI checks each is current with cook update --dry-run.

    3. 3

      The current standard is at every seat

      ProblemA new teammate clones a project and finds last month's version of how the team works.

      SolutionA new teammate finds the current standard in the project itself, on the first day.

    4. 4

      What a standard wrote is marked

      ProblemPasting files to catch up carries a colleague's own settings along, and nobody can say which lines are the standard.

      SolutionWhat a standard wrote is marked, and the team's own lines stay as they were.

    5. 5

      A dropped standard takes everything it brought

      ProblemA tool leaves lines across half a dozen files, and what nobody finds stays behind when the team moves on.

      SolutionA dropped standard leaves every file it touched and takes nothing else. Projects read its files without Cook installed, so no tool stays behind.

    The recipes

    A standard, written down and replicable

    Write a standard once. A recipe is a short Groovy file. Cook it into one project or fifty, at the same version, each with its own parameters.

    1. {% include icons/terminal.svg %}
      Cook

      The recipe runs against the files as they are now.

    2. {% include icons/layers.svg %}
      Plan

      Each model turns its calls into sections, keys and files.

    3. {% include icons/scale.svg %}
      Review

      One diff for the whole batch, cook.lock included.

    4. {% include icons/package.svg %}
      Write

      On yes, written and recorded in cook.lock. A failed write rolls back.

    recipes/Notes.groovy
    /** A model: the files one program reads. */
@Ingredient
class Notes {
  private final List<String> lines = [], ignored = []

  void add(String line) { lines << line }
  void ignore(String path) { ignored << path }

  /** Write a whole file. */
  @File(path = 'NOTES.md')
  String file() {
    lines ? lines.collect { "- ${it}\n" }.join() : null
  }

  /** Write one marked section of a shared file. */
  @Section(path = '.gitignore', id = 'scratch')
  List<String> ignoredPaths() { ignored ?: null }
}

@ingredient(Notes) def notes

notes.add('Run the tests before committing.')

    @Ingredient
class Editor {
  private Boolean format
  private Integer tabSize

  void formatOnSave() { format = true }
  void indent(int spaces) { tabSize = spaces }

  @Key(path = '.vscode/settings.json',
       segments = ['editor.formatOnSave'])
  Boolean formatOnSaveKey() { format }

  /** A second key, written only when the recipe sets an indent. */
  @Key(path = '.vscode/settings.json',
       segments = ['editor.tabSize'])
  Integer tabSizeKey() { tabSize }
}

    The procedures

    Cook, update, discard, replicate, check, help

    The commands, and the record of what they wrote.

    {% include icons/chef-hat.svg %}cook <recipe>...

    Cooks recipes left to right in one batch.

    {% include icons/tag.svg %}cook update [<name>...]

    Moves recipes to newer releases in their range, as one diff to approve.

    {% include icons/trash-2.svg %}cook discard <name>...

    Takes out exactly what a recipe put in, without running it.

    {% include icons/repeat.svg %}cook replicate [<name>...]

    Rebuilds what the lock records, including ignored output a fresh clone lacks.

    {% include icons/circle-check.svg %}cook check [<name>...]

    Writes nothing. Exits 1 when the files differ from the lock, 2 on an error.

    {% include icons/book-open.svg %}cook help <recipe>...

    Shows what a recipe writes and which parameters it takes, without running it.

    #seed writes AGENTS.md and a permission policy. #connect renders the policy into Claude Code and Codex, and writes links the repository commits, so a fresh clone or a cloud session already has the setup.
